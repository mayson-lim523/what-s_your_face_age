## 2. 프로그램 4-3 손실 함수와 최적화

### 최종 코드

```python
# 프로그램 4-3 손실 함수와 최적화 알고리즘 설정하기

LR = 0.001                      # 발표 자료 실험 조건 중 하나

criterion = nn.CrossEntropyLoss()          # 다중 분류용 손실 함수
optimizer = torch.optim.Adam(model.parameters(), lr=LR)

print(criterion)
print(optimizer)
```

### 각 줄의 의미

| 코드 | 의미 |
|---|---|
| `nn.CrossEntropyLoss()` | 모델 출력(점수, logit)에 내부적으로 **softmax → −log(정답 확률)**을 적용한다. 정답 확률이 높을수록 손실이 작다. 그래서 모델 마지막에 softmax를 넣지 않는다 (넣으면 두 번 적용됨). 라벨은 정수(0~6) 그대로 넣는다 |
| `model.parameters()` | 학습할 가중치 390,695개를 optimizer에 넘긴다. **반드시 `model.to(device)` 다음에** 만들어야 한다 |
| `Adam(lr=0.001)` | 파라미터마다 이동 폭을 자동 조절하는 최적화 알고리즘. 학습률 0.001은 교재 값이자 발표 자료의 실험 조건 중 하나 |

### 실행 결과에서 본 Adam 설정

| 항목 | 값 | 의미 |
|---|---|---|
| `lr` | 0.001 | 한 번에 가중치를 움직이는 폭 |
| `betas` | (0.9, 0.999) | 기울기의 평균·크기를 기억하는 정도 (기본값) |
| `weight_decay` | 0 | 가중치 크기 규제 꺼짐. 과적합이 심하면 실험 후보 |

### 클래스 가중치는 아직 적용하지 않음

- training 데이터에서 50대(6,801장), 60세 이상(5,269장)이 다른 나이대(약 12,000장)의 절반 정도다.
- `CrossEntropyLoss(weight=...)`에 `전체 개수 / (클래스 수 × 클래스 개수)`를 넣으면 보정할 수 있다 → 50대 1.51, 60세 이상 1.95.
- **100장 과적합 테스트에는 불필요**해서 빼고, 본 학습 때 적용한다. 팀원 ResNet-50·ConvNeXt 코드도 같은 식을 쓴다 (`[0.89 0.85 0.85 0.85 0.85 1.51 1.94]`).

## 3. 프로그램 4-4 학습 루프

### 교재와 달라진 점

| 교재 | 수정 | 이유 |
|---|---|---|
| 없음 | `torch.manual_seed(SEED)` (4-1 상단) | 모델 초기 가중치와 배치 순서를 고정해 재현 가능하게 |
| 없음 | `model.train()` / `model.eval()` | Dropout, BatchNorm이 모드에 따라 다르게 동작 |
| 없음 | `.to(device)` | 데이터를 모델과 같은 GPU로 |
| loss 합계만 출력 | 평균 loss와 **정확도** 계산 | 에폭 단위로 성능 비교 |
| 없음 | **검증 루프** (`torch.no_grad()`) | 처음 보는 데이터에서의 성능 확인 |
| 없음 | `history`에 기록 | 4-5 학습 곡선용 |
| 없음 | val 정확도 최고일 때 `state_dict` 저장 | 과적합 전 가장 좋은 시점의 모델 보존 |
| 배치 32, 3 에폭 | 배치 **64**, 에폭 **20** | 팀원(ResNet-50, ConvNeXt) 설정과 통일 |

### 최종 코드 (과적합 테스트 설정 상태)

```python
# 프로그램 4-4 학습 루프 실행하기

# 과적합 테스트: train에도 증강을 끈다 (끝나면 이 줄을 지우거나 주석 처리)
train_dataset.transform = val_transform

NUM_EPOCHS = 100
SAVE_PATH = "small_cnn_best.pth"

history = {"train_loss": [], "train_acc": [], "val_loss": [], "val_acc": []}
best_val_acc = 0.0

for epoch in range(NUM_EPOCHS):
    # ---------- 학습 ----------
    model.train()
    running_loss, correct, total = 0.0, 0, 0

    for images, labels in train_loader:
        images, labels = images.to(device), labels.to(device)

        optimizer.zero_grad()                      # 이전 기울기 초기화
        outputs = model(images)
        loss = criterion(outputs, labels)
        loss.backward()                           # 역전파
        optimizer.step()                      # 가중치 업데이트

        running_loss += loss.item() * images.size(0)
        correct += (outputs.argmax(dim=1) == labels).sum().item()
        total += labels.size(0)

    train_loss = running_loss / total
    train_acc = correct / total

    # ---------- 검증 ----------
    model.eval()
    running_loss, correct, total = 0.0, 0, 0

    with torch.no_grad():
        for images, labels in val_loader:
            images, labels = images.to(device), labels.to(device)                              # 학습 루프와 같은 방식으로 GPU로
            outputs = model(images)
            loss = criterion(outputs, labels)

            running_loss += loss.item() * images.size(0)
            correct += (outputs.argmax(dim=1) == labels).sum().item()
            total += labels.size(0)

    val_loss = running_loss / total
    val_acc = correct / total

    # ---------- 기록 ----------
    history["train_loss"].append(train_loss)
    history["train_acc"].append(train_acc)    
    history["val_loss"].append(val_loss)
    history["val_acc"].append(val_acc)                                  # 나머지 3개도 append

    print(f"Epoch {epoch+1:2d}/{NUM_EPOCHS} | "
          f"train loss {train_loss:.4f} acc {train_acc:.3f} | "
          f"val loss {val_loss:.4f} acc {val_acc:.3f}")

    # ---------- 최고 모델 저장 ----------
    if val_acc > best_val_acc:
        best_val_acc = val_acc
        torch.save(model.state_dict(), SAVE_PATH)

print("best val acc:", best_val_acc)
```

4-1에서 함께 바꾼 부분:

```python
SEED = 42

```

## 4. 공부한 내용

### 4-1. 학습 5단계 (배치마다 반복)

| 순서 | 코드 | 하는 일 | 비유 |
|---|---|---|---|
| 1 | `optimizer.zero_grad()` | 지난 배치의 기울기 지우기 | 지도를 새로 펴기 |
| 2 | `outputs = model(images)` | 순전파 | |
| 3 | `loss = criterion(outputs, labels)` | 손실 계산 | |
| 4 | `loss.backward()` | 역전파: 가중치마다 기울기를 계산해 `.grad`에 저장 (가중치는 아직 안 바뀜) | 경사 측정 |
| 5 | `optimizer.step()` | 기울기를 보고 가중치를 lr만큼 이동 (실제로 "배우는" 순간) | 한 걸음 걷기 |

- **`zero_grad`가 필요한 이유**: PyTorch는 `backward()`할 때 기울기를 **덮어쓰지 않고 더한다(누적)**. 안 지우면 이전 배치들의 기울기가 계속 쌓여 엉뚱한 방향으로 업데이트된다.

### 4-2. `model.train()` / `model.eval()` / `torch.no_grad()`

| 층 | `train()` 모드 | `eval()` 모드 |
|---|---|---|
| Dropout | 무작위 30% 끔 | 끄지 않음 |
| BatchNorm | 현재 배치의 평균·분산 사용, 누적 통계 업데이트 | 학습 중 누적한 평균·분산 사용 |

- `model.eval()`은 **층의 동작 방식**을, `torch.no_grad()`는 **기울기 기록**을 바꾼다. 역할이 달라서 검증 때 둘 다 쓴다.
- 매 에폭 시작마다 `model.train()`을 다시 호출해야 한다. 안 하면 이전 에폭 검증에서 바뀐 eval 모드로 학습하게 되는데, **에러가 나지 않아 알아채기 어려운 버그**다.
- 검증 구간에는 `zero_grad`, `backward`, `step`이 없다. 가중치를 바꾸면 안 되기 때문이다.

### 4-3. 정확도와 평균 손실 계산

```python
running_loss += loss.item() * images.size(0)   # 배치 평균 × 배치 크기 = 배치 합계
correct += (outputs.argmax(dim=1) == labels).sum().item()
total += labels.size(0)
```

- `outputs`는 `(B, 7)` → `dim=0`은 사진, `dim=1`은 나이대 7개. **한 사진 안의 7개 점수 중** 가장 큰 위치를 골라야 하므로 `dim=1`이다.
- `loss`는 배치 **평균**이다. 100장 = 64장 + 36장처럼 배치 크기가 다르면 평균끼리 더할 때 부정확해진다. 배치 크기를 곱해 합계로 바꾼 뒤, 마지막에 전체 개수(`total`)로 나눈다.

### 4-4. `history` 딕셔너리

```python
history = {"train_loss": [], "train_acc": [], "val_loss": [], "val_acc": []}
history["train_loss"].append(train_loss)   # 이름표로 리스트를 꺼내 끝에 추가
```
- 에폭마다 값이 하나씩 쌓여서 리스트마다 값이 `NUM_EPOCHS`개가 된다 → 4-5에서 `plt.plot(history["train_loss"])`로 학습 곡선을 그린다.

### 4-5. `torch.save(model.state_dict(), ...)`

- 모델 객체 전체가 아니라 **가중치만** 딕셔너리로 저장한다. 클래스 코드나 파일 위치가 바뀌어도 `SmallCNN()`을 새로 만들고 `load_state_dict`로 넣으면 된다 (Gradio 시연 때도 같은 방식).
- val 정확도가 갱신될 때만 덮어쓰므로, 마지막 에폭이 아니라 **가장 좋았던 에폭**의 모델이 남는다. (팀원 ResNet-50도 12 에폭에서 멈췄지만 저장된 것은 8 에폭 모델)

### 4-6. 시드 위치

```
수정 전                                    수정 후
4-1  데이터 로딩                           4-1  torch.manual_seed(SEED)  ← 여기로 이동
4-2  model = SmallCNN()  ← 무작위 초기화    4-1  데이터 로딩
4-4  torch.manual_seed(SEED) ← 너무 늦음    4-2  model = SmallCNN()  ← 고정된 초기화
```
- 모델을 만드는 순간 conv·fc 가중치가 무작위로 정해지므로, 시드는 **모델 생성 전**에 고정해야 한다.
- 확인: 수정 후 두 번 실행했을 때 4-1 라벨 출력(`tensor([5, 1, 3, 4, 0, 1, 5, 6, 4, 4])`)과 1~2 에폭 값(2.0320, 1.7732)이 **완전히 같았다**.
- 3 에폭부터 소수점 넷째 자리가 조금 달라진다(1.9776 → 1.9775). GPU(cuDNN) 연산 순서에서 생기는 아주 작은 차이로, 결과 해석에는 영향이 없다.

## 5. 과적합 테스트 결과

**조건**: train 100장 / val 100장, 증강 끔, 배치 64, Adam lr 0.001, 시드 42

### 5-1. 1차: 20 에폭 → 미통과 (버그 아님)

| 에폭 | train loss | train acc | val loss | val acc |
|---:|---:|---:|---:|---:|
| 1 | 2.0320 | 0.180 | 1.9711 | 0.080 |
| 10 | 1.3329 | 0.490 | 2.3902 | 0.170 |
| 20 | 1.1355 | 0.610 | 2.8109 | 0.110 |

- train loss는 꾸준히 감소했지만 train acc가 **0.61에서 끝났다** (기준 0.9).
- **버그가 아니라고 판단한 이유**: 버그가 있으면 train loss가 약 1.95(= ln 7, 아무것도 모르는 상태) 근처에서 멈춘다. 계속 내려가고 있었고, train은 좋아지고 val은 나빠지는 과적합 패턴도 나왔다.
- **원인: 업데이트 횟수 부족.** 배치 64면 100장은 에폭당 2번(64장 + 36장)만 업데이트돼서 20 에폭 = **40번**뿐이다. (교재 MNIST: 5000장 ÷ 32 × 3 에폭 ≈ 470번) Dropout이 켜져 있어 외우는 속도도 조금 느리다.

### 5-3. 해석

| 관찰 | 의미 |
|---|---|
| train acc 0.18 → 49 에폭 0.90 → 85·98 에폭 **1.000** | 100장을 완전히 외울 수 있음 → **데이터 로딩·모델·역전파·업데이트가 모두 정상** |
| train loss 2.03 → 0.19 | 학습이 제대로 진행됨 |
| val loss 1.97 → 4.28, **3 에폭부터 증가** | 외운 100장 외에는 일반화가 안 되는 전형적인 **과적합**. 이 테스트에서 기대한 결과 |
| val acc 0.06~0.20 | 7개 중 찍는 수준(약 0.14). 100장으로는 나이를 배울 수 없으므로 정상 |
| train acc가 오르락내리락 (0.99 → 0.95 등) | Dropout이 학습 중 매번 다른 30%를 끄기 때문 |

- 팀원 ResNet-50에서도 같은 현상이 나왔다 (8 에폭 이후 학습 손실은 감소, 검증 손실은 증가). 우리는 100장뿐이라 3 에폭부터 훨씬 빨리 나타났다.
- 저장된 `small_cnn_best.pth`는 테스트용이라 의미 없는 모델이다. 본 학습 때 덮어쓴다.

## 6. 팀원 코드와 조건 비교

팀원의 ResNet-50·ConvNeXt 코드(`ResNet50/ResNet50/code/`, `ConvNeXt/ConvNeXt/code/train_convnext.py`)와 README를 확인했다.

### 6-1. 데이터 분할은 같다

- 팀원은 `make_split_csv.py`로 `split_result_224`의 training/validation/testing **폴더 구조를 그대로 CSV로 바꿔서** 사용한다.

- CSV 개수(학습 71,735 / 검증 15,288)가 내 `ImageFolder` 출력과 **정확히 같다** → 내 코드를 CSV 방식으로 바꿀 필요 없음.

### 6-2. 본 학습 전에 맞출 것

| 항목 | 팀원 | 나 (현재) | 계획 |
|---|---|---|---|
| 에폭 / 배치 | 20 / 64 | 100 (테스트) / 64 | 본 학습은 20 |
| 증강 | 확대·자르기(0.9~1.0), 반전, ±10°, **밝기+대비** ±0.2 | 반전, ±10°, 밝기 | 통일 |
| 손실 가중치 | 적용 | 미적용 | 적용 |
| 평가 지표 | acc, **한 칸 차이 acc, macro-F1** | acc | 추가 |
| 최고 모델 기준 | val **macro-F1** | val acc | 변경 |
| 결과 기록 | `history.csv` | `history` 딕셔너리 | 같은 열 이름으로 CSV 저장 |
| 최적화 | AdamW (wd 0.05) + 워밍업·코사인 스케줄 | Adam | 통일 검토 |
| 조기 종료 | macro-F1 4번 연속 정체 시 | 없음 | 통일 검토 |

### 6-3. 따라 하지 않을 것 (사전학습 모델 전용)

| 항목 | 팀원 | 작은 CNN에서는 |
|---|---|---|
| `pretrained=True` | ImageNet 가중치 | 처음부터 학습하는 것이 역할 |
| 첫 1 에폭 출력층만 학습 | 미리 학습된 몸통 보호 | 얼릴 몸통이 없음 |
| 몸통 lr 1e-4 / 출력층 1e-3 | 미세조정용 | 모든 층이 무작위 초기값 → 전체 1e-3 |

→ 발표 때: "사전학습 모델은 미세조정이라 작은 학습률, 작은 CNN은 처음부터 학습이라 큰 학습률을 썼다."

### 6-4. ⚠️ 팀 논의 필요: `small_cnn` 정의가 두 가지

팀원 `common.py`의 `build_model("small_cnn")`에도 작은 CNN이 정의되어 있는데 구조가 다르다.

| | 내 모델 | 팀원 `common.py` |
|---|---|---|
| 블록 수 | 4 | 4 |
| 블록당 conv | 1개 | 2개 (VGG 방식) |
| 전체 conv 층 | 4 | 8 |
| 파라미터 수 | 390,695 | 약 117만 |

→ 결과표에 들어갈 작은 CNN은 하나여야 한다. 어느 정의로 갈지 팀에서 결정한다.
