- **날짜**: 2026-11-10

- **담당**: 임성빈 — 작은 CNN(4층) 처음부터 학습 (사전학습 없는 비교 기준 모델)
- **작업 범위**: 교재 프로그램 4-2(2층 CNN)를 얼굴 나이대 분류용 4층 CNN으로 수정
- **상태**: ✅ 완료 (출력 shape, 파라미터 수 확인)

---

## 1. 목표

교재의 MNIST용 2층 CNN을 바탕으로, 224×224 RGB 얼굴 이미지를 7개 나이대로 분류하는 4층 CNN을 직접 작성한다.

---

## 2. 교재 코드와 비교

| 교재 (MNIST) | 우리 모델 | 바꾼 이유 |
|---|---|---|
| `Conv2d(1, 8, ...)` | `Conv2d(3, 32, ..., bias=False)` | 입력이 RGB 3채널이고, 얼굴은 숫자보다 복잡해서 채널을 늘림 |
| conv 2개 (1→8→16) | conv **4개** (3→32→64→128→256) | 2층 → 4층 |
| BN 없음 | conv마다 `BatchNorm2d` | 층이 깊어지면 학습이 불안정해져서 추가 |
| pool은 conv1 뒤에만 | **블록마다** pool | 224를 14까지 줄여야 함 (224→112→56→28→14) |
| `view` 후 `Linear(16*14*14, 10)` | `AdaptiveAvgPool2d(1)` → `view` → `Dropout` → `Linear(256, 7)` | 그대로 펼치면 FC 입력이 50,176개라 과적합 위험. GAP로 256개로 줄임 |
| `model = SmallCNN()` | `SmallCNN().to(device)` | GPU에서 학습 |

**블록 하나 = 교재의 `conv → relu → pool` + BN**이고, 이것을 4번 반복한 뒤 GAP와 Dropout을 붙인 구조다.

---

## 3. 모델 구조

| 단계 | 구성 | 출력 shape |
|---|---|---|
| 입력 | | (B, 3, 224, 224) |
| 블록 1 | Conv(3→32) → BN → ReLU → MaxPool | (B, 32, 112, 112) |
| 블록 2 | Conv(32→64) → BN → ReLU → MaxPool | (B, 64, 56, 56) |
| 블록 3 | Conv(64→128) → BN → ReLU → MaxPool | (B, 128, 28, 28) |
| 블록 4 | Conv(128→256) → BN → ReLU → MaxPool | (B, 256, 14, 14) |
| 헤드 | GAP → view → Dropout(0.3) → Linear(256→7) | (B, 7) |

---

## 4. 최종 코드 (프로그램 4-2)

```python
# 프로그램 4-2 4층 CNN 모델 구성하기

import torch.nn as nn

NUM_CLASSES = 7

class SmallCNN(nn.Module):
    def __init__(self, num_classes=NUM_CLASSES):
        super().__init__()
        # 블록 1: 3 → 32
        self.conv1 = nn.Conv2d(3, 32, kernel_size=3, padding=1, bias=False)
        self.bn1   = nn.BatchNorm2d(32) ### ()안은 채널수...?
        # 블록 2: 32 → 64
        self.conv2 = nn.Conv2d(32, 64,kernel_size=3, padding=1, bias=False)
        self.bn2   = nn.BatchNorm2d(64)
        # 블록 3: 64 → 128
        self.conv3 = nn.Conv2d(64, 128,kernel_size=3, padding=1, bias=False)
        self.bn3   = nn.BatchNorm2d(128)
        # 블록 4: 128 → 256
        self.conv4 = nn.Conv2d(128, 256,kernel_size=3, padding=1, bias=False)
        self.bn4   = nn.BatchNorm2d(256)

        self.pool    = nn.MaxPool2d(2, 2)   ###(kernel_size, stride)
        self.gap     = nn.AdaptiveAvgPool2d((1,1))
        self.dropout = nn.Dropout(p=0.3)
        self.fc      = nn.Linear(256, num_classes)

    def forward(self, x):
        x = self.pool(torch.relu(self.bn1(self.conv1(x))))   # (B, 32, 112, 112)
        x = self.pool(torch.relu(self.bn2(self.conv2(x))))   # (B, 64, 56, 56)
        x = self.pool(torch.relu(self.bn3(self.conv3(x))))   # (B, 128, 28, 28)
        x = self.pool(torch.relu(self.bn4(self.conv4(x))))   # (B, 256, 14, 14)
        x = self.gap(x)                                       # (B, 256, 1, 1)
        x = x.view(x.size(0), -1)                             # (B, 256)
        x = self.dropout(x)
        x = self.fc(x)                                        # (B, 7)
        return x

model = SmallCNN().to(device)    # 모델을 GPU로

out = model(images.to(device))
print(out.shape)                   # torch.Size([32, 7])

n_params = sum(p.numel() for p in model.parameters())
print(n_params)                    # 390695
```

`forward`의 한 줄은 **안쪽부터** 실행된다: ① conv(특징 추출) → ② bn(채널별 정규화) → ③ relu(음수 제거) → ④ pool(크기 절반)

## 6. 공부한 내용

### 6-1. 출력 크기 공식: `(H + 2P − K) / S + 1`

| 기호 | 뜻 | 우리 conv |
|---|---|---|
| H | 입력 **높이(픽셀)** — 채널 수가 아님. 가로(W)도 같은 공식 | 224 |
| P | padding (테두리에 덧붙이는 칸 수) | 1 |
| K | kernel_size (필터 크기) | 3 |
| S | stride (한 번에 이동하는 칸 수) | 1 |

- PyTorch 이미지 텐서는 `(B, C, H, W)` 순서다. 공식은 H, W(공간 크기)를 계산한다. 채널 수는 `Conv2d`의 `out_channels`가 그대로 출력 채널이 된다.
- **`+1`의 의미**: `H − K`는 필터가 이동할 수 있는 거리, `+1`은 처음 놓인 위치다. 울타리 간격이 2개면 기둥은 3개인 것과 같다.
  - 예: 가로 5칸 이미지 + 3칸 필터 → `(5 − 3) / 1 + 1 = 3`곳
- **conv는 채널을 바꾸고 크기는 유지**, **pool은 크기를 절반으로 줄이고 채널은 유지**한다.

### 6-2. padding=1을 쓰는 이유

| 연산 | K | P | S | 224 입력 |
|---|---|---|---|---|
| conv, padding=1 | 3 | 1 | 1 | 224 (유지) |
| conv, padding=0 | 3 | 0 | 1 | 222 (K−1 = 2칸 감소) |
| MaxPool2d(2, 2) | 2 | 0 | **2** | 112 (**절반**) |

- padding=0이면 절반이 아니라 2칸만 줄어든다. 절반으로 줄이는 것은 stride=2(pool)의 역할이다.
- padding=0으로 4층을 쌓으면 224→222→111→109→54→52→26→24→**12**가 된다. 홀수에서 소수점이 버려지고, 가장자리 정보(이마 끝, 턱선 등)를 덜 보게 된다.
- → **conv는 padding=1로 크기 유지, 줄이는 것은 pool에만 맡긴다.**

### 6-3. 채널 3 → 32 → … → 256의 근거

- **3**: RGB라서 고정값이다.
- **채널 = 필터 개수 = 찾는 패턴의 종류 수**. 첫 층은 단순한 패턴(엣지, 색)만 찾으므로 32개로 충분하고, 깊어질수록 복잡한 패턴(주름, 윤곽)을 찾기 위해 늘린다.
- **크기가 절반이 될 때 채널을 2배로**: ResNet 논문(He et al., 2015)과 VGGNet의 설계 관례다. conv 계산량은 `H × W × C_in × C_out × 9`에 비례하는데, H·W가 ½씩(÷4) 줄고 C_in·C_out이 2배씩(×4) 늘어 **층별 계산량이 일정하게 유지**된다. 블록 2→3→4의 계산량이 정확히 같다.
- **시작 채널 32**: 모델 크기와 과적합 사이의 절충이다.

| 시작 채널 | 파라미터 수 | 특징 |
|---|---:|---|
| 16 | 약 9.9만 | 빠르지만 표현력이 부족할 수 있음 |
| **32** | **약 39만** | 중간 (채택) |
| 64 | 약 156만 | 처음부터 학습하면 과적합 위험이 큼 |

> 채널이 2배가 되면 파라미터는 약 4배가 된다 (conv 파라미터가 `C_in × C_out`에 비례).

### 6-4. 각 층의 ( ) 안 인자

| 층 | 인자 | 뜻 | 우리 값 |
|---|---|---|---|
| `MaxPool2d(kernel_size, stride)` | 창문 크기, 이동 칸 수 | 창문 안 최댓값만 남김 | (2, 2) → 크기 절반 |
| `AdaptiveAvgPool2d(output_size)` | **원하는 출력 크기** (창문 크기가 아님) | 입력이 몇이든 출력 크기 고정, 평균 | (1, 1) → 채널마다 숫자 1개 |
| `Dropout(p)` | 0으로 끌 확률 | 학습 때만 무작위로 30% 끔 → 특정 특징에 의존하지 않게 함 | 0.3 |
| `Linear(in, out)` | 들어오는 개수, 나가는 개수 (배치 제외) | 모든 입력과 출력을 연결 | (256, 7) |
| `BatchNorm2d(num_features)` | **채널 수** | 채널마다 따로 정규화, 채널마다 γ·β 2개 학습 | 앞 conv의 출력 채널과 같아야 함 |

- `Dropout`과 `BatchNorm`은 `model.train()` / `model.eval()` 상태에 따라 동작이 달라진다. → 4-4에서 반드시 전환할 것.

### 6-5. Conv1d / Conv2d / Conv3d

숫자는 **필터가 움직이는 방향의 개수**다.

| | 입력 shape | 움직이는 방향 | 주로 쓰는 데이터 |
|---|---|---|---|
| Conv1d | (B, C, L) | 길이 | 센서 시계열, 음성, 문장 |
| **Conv2d** | (B, C, H, W) | 세로, 가로 | **이미지** |
| Conv3d | (B, C, D, H, W) | 깊이, 세로, 가로 | 동영상, CT·MRI |

- **채널(C)은 움직이는 방향이 아니다.** 필터는 RGB 3채널을 한 번에 덮고 세로·가로로만 움직인다.
- `model.conv1.weight.shape` = `[32, 3, 3, 3]` (out, in, kH, kW) → 필터 하나가 `3 × 3 × 3` 상자이고, 그 필터가 32개다.
